# dsh-project-memory

**言語:** [English](./README.md) · [简体中文](./README.zh-CN.md) · 日本語 · [Español](./README.es.md)

[DeepSeek Harness](https://github.com/deepseek-ai) 向けの、プロジェクト単位で永続する知識・開発状態メモリのプラグインです。

セッションが終わるとき、コンテキストが圧縮（compaction）されるとき、ブランチを切り替えるとき —— エージェントはすべてを忘れます。数十セッションにわたって存続するプロジェクトでは、それは同じ意思決定を何度も導き直し、同じ文書を何度も読み直し、同じ失敗を繰り返すことを意味します。このプラグインは、プロジェクトに**コンテキストウィンドウの中ではなく、リポジトリの中に住む**記憶を与えます。

**ホスト側のみの [cordis](https://github.com/deepseek-ai/cordis) プラグイン**です。エージェントツール、システムプロンプトの一節、スラッシュコマンドを登録します。ブラウザ側の実装はなく、DSH 本体にも変更を加えません。

```
MIT ライセンス · Node 20+ · ホスト側のみ、クライアント側なし
```

## 意図的に三つのシステム

**System A —— 文書知識。** リポジトリ内の Markdown が信頼できる情報源です。プラグインはそれを索引化し、検索し、指定した節を読みます。権威ある文書を書き換えることは決してありません。変更を提案するときは `docs/proposals/` に書きます。

**System B —— 開発状態。** タスク、進捗、ブロッカー、決定、次のステップ、git の事実、引き継ぎメモは、ツール呼び出しによって永続化されるため、再起動や圧縮を生き延びます。**永続化するのはそのツール呼び出しです。** `state_update` を一度も呼ばないエージェントには状態メモリは生まれません —— プラグインは会話を走査して推測したりしません。

**System C —— メモリ原子（memory atoms）。** 圧縮サマリと、ユーザーが明示した規則から抽出された、アドレス可能で永続的なレコード。それが次のリクエストへ**選択的に**呼び戻されます。これが「圧縮すなわち損失」への答えです。チェックポイントのサマリは元のターンを置き換え、それが落としたものは失われます。原子はその内容に、コンテキストウィンドウの外で第二の人生を与えます —— サマリを生き延びる幸運に頼るのではなく、関連性によって検索される形で。

呼び戻しは全部を流し込むのではなく、疎なゲーティングに従います。スコアリングは決定的（語彙の重なり、種別の優先度、強化回数、新しさ）で、選択は疎（多数から少数を順位付けて選ぶ）で、コストには上限があります（呼び出し側が誤って超えられないトークン上限）。これは MemGPT の構図 —— コンテキストウィンドウをワーキングメモリ、ストアをより大きな記憶空間とみなし、必要に応じて交換する —— を、Mixture-of-Experts のゲートとして表現したものです。種別がエキスパート、原子はエキスパート内で競合し、softmax が**このリクエスト**でどのエキスパートを活性化するかを決めます。

語彙スコアでは足りないとき、サブエージェントをルーターとして使えます。三つの段階:

| `routerTier` | 動作 | コスト |
| --- | --- | --- |
| `off` | 決定的ゲーティングのみ。 | 無料 |
| `smart`（既定） | 決定的ゲーティング。関連するものを何も選べなかったか、一致が弱いときだけルーターへ昇格。 | ほぼ無料。安い経路が失敗したときだけ 1 回 |
| `always` | 毎ステップでルーターサブエージェントに問い合わせる。 | 1 ステップ 1 回 —— 安価なモデルと組み合わせる |

`routerProvider` と `routerModel` の**両方**が設定されるまで `smart` は一切コストをかけません。したがって導入直後はモデル呼び出しを消費しません。

## やらないこと

- `AGENTS.md`、`docs/decisions/`、`docs/adr/`、`.git/` を変更しません。`docs_sync` はこれらのパスを拒否し、拒否した理由を明示します。
- commit、branch、push を行いません。git の事実を記録するだけで、git 操作は実行しません。
- 状態を黙って捏造しません。すべての変更は比較交換（compare-and-set）付きリビジョンを持つ `state_update` を通り、同時書き込みは上書きではなく競合として報告されます。

## インストール

コマンド一つです。マニフェストが `dsh.bundle` を宣言しているため、ホスト自身が依存関係**と**バンドルエントリの両方を追加します —— `reconcileProfilePlugins()` が、その宣言を持つ新規インストール済み依存関係を昇格させます。

```powershell
$dsh = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop add -w "link:D:\path\to\dsh-memory"
```

その後ホストを再起動します。`project_inspect` で確認してください。プロジェクトルートと索引化された文書数が返れば、プラグインは動作しています。

プロファイルを手で編集する方法もあります（`dependencies` エントリと `dsh.profile.bundles` エントリ）が、こちらは遅いうえに中途半端になりやすい —— バンドルエントリなしの依存関係はインストールされるだけで、決してロードされません。

pnpm は `link:` 依存関係が対象の `node_modules` から peer を解決しないと警告します。ここでは想定内で無害です。このプラグインには実行時依存がなく、唯一の peer（`@deepseek-ai/dsh-llm`）はホストが提供します。

バンドルパッチ（`cordis.patch.yml`）は 1 行を挿入します:

```yaml
- insert:
    - id: project-memory
      name: '@dsh-external/dsh-project-memory'
```

既定値で足りない場合は、その行に設定を渡せます:

```yaml
- insert:
    - id: project-memory
      name: '@dsh-external/dsh-project-memory'
      config:
        l0Budget: 300
        l1Budget: 1200
        registerCommands: true
        routerTier: smart
```

### アップグレード

`engines.dsh` は `>=0.2.0-rc.0 <0.3.0` です。広く開くのではなく意図的に狭くしています。ホストのマイナーリリースでツールスキーマのサブセットや注入メッセージの形が変わりうるため、その場合このプラグインはインストール時に大声で失敗するのではなく、**マウント時に静かに失敗**します。この範囲は実際にテストした版（0.2.1-rc.2）を述べており、より新しいホストに対してスイートを再実行したうえで広げてください。

`engines.dsh` が存在する場合、ホストは**それだけ**を読み、`peerDependencies` の範囲は完全に無視します（`dsh-app-boot` の `unmetRequirements`）。peer エントリは、このパッケージが実行時に何を import するかの宣言として残してあり、二つ目のゲートではありません。

`npm run test:host` がこれを直接検査します。`tests/compat.mjs` が実際のマニフェストをホスト自身の `evaluatePluginCompatibility` に渡すので、範囲が実行時と食い違えばテストが落ちます。

## ツール

15 個。見慣れないセッションで最初に呼ぶべきは `memory_status` です。

| ツール | 何に答えるか |
| --- | --- |
| `memory_bootstrap` | 新しいセッションに必要なすべてを、トークン予算内で 1 回で返す。 |
| `memory_status` | 初期化済みか？リビジョンは？git に対して古いか？原子はいくつ？索引の再構築も可能。 |
| `memory_search` | どの文書がこれを扱っているか？状態・種別・パスのフィルタ付きで順位付け。 |
| `memory_read` | 文書、またはその `##` 節を一つ読む。長さ上限あり、データとして枠付け。 |
| `memory_recall` | 保存済み原子のうち、この問いに関連するものは？順位・予算付きで、経路と信頼度も。 |
| `memory_remember` | 永続的な事実・制約・決定を保存し、後のセッションから見つけられるようにする。 |
| `memory_forget` | id 指定で原子を退役させる。墓碑は粘着的で、再抽出でも復活しない。 |
| `state_get` | 現在のタスク、進捗、ブロッカー、決定、次のステップ。 |
| `state_update` | 変更を記録する。比較交換方式。競合は報告され、上書きされない。 |
| `state_handoff` | セッション終わりの引き継ぎメモを書き、次のセッションが方向を持って始められるようにする。 |
| `project_init` | このプロジェクト用に `.dsh-memory/` を作る。自動では何も作られない。 |
| `project_inspect` | ルート、git の事実、メモリの有無、索引状態 —— 読み取り専用の診断。 |
| `docs_check` | 文書集合全体の front-matter と状態の問題。 |
| `docs_sync` | 文書を更新するか変更を提案する。保護パスは拒否。 |
| `architecture_check` | `.dsh-memory/arch.json` に対する決定的な import ルール検査。 |

### コマンド

`/memory-status`、`/memory-context`、`/memory-init`、`/memory-handoff`、`/memory-recall`、`/memory-route`、`/memory-forget`、`/memory-sync`、`/architecture-check`。

`/memory-route` はドライランです。現在の段階がどの経路を取るか、その理由を、**モデル呼び出しを消費せずに**示します。

### コンテキスト注入

セッションの最初のステップで、プラグインはベースライン（プロジェクト識別、git の事実、現在のタスク、不変条件、次のステップ、ブロッカー、決定、文書マップ）を注入します。`l0Budget`/`l1Budget` に収まります。再送は識別が変わったときだけで、送る前にセッションのサーフェスを走査するので、圧縮済み・再開済みのセッションに重複は渡りません。再送もベースラインであり、何も変わっていなければ何も注入しません。

さらに各ステップは **recall ブロック**を受け取ることがあります。そのステップのリクエストに対して選ばれた原子と、その種別・出所・スコアです。独立したメッセージで独自のソース種別を持つため、レビューする人は「永続ベースライン」と「このステップ用に計算された選択」を区別できます。セッションのサーフェスに対して**原子集合**で重複排除されます —— モデルがすでに見られる原子を述べ直すのは、このシステムが守ろうとしている予算を消費することになるからです。一方、**新しい**選択（または圧縮に影を落とされたもの）は依然として送られます。

ベースラインは**プラグイン所有の、nonce フェンスで囲まれたユーザーメッセージ**として届きます。プロジェクトのテキストはデータであり、決して指示ではありません。役割接頭辞は中和され、"ignore previous instructions" のような言い回しは除去され、不可視文字と双方向制御文字は削除され、コードフェンスは閉じられて文書が枠から抜け出せません。recall の原子にも同じ枠付けが適用されます。

## ストレージ構成

すべてプロジェクトルートの `.dsh-memory/` の下にあります。コミットしても無視しても、どちらも筋が通ります。コミットすればチームで状態を共有でき、無視すれば各開発者が私的なものを持てます。

```
.dsh-memory/
  project.json          安定した projectId + 初回に見た git の事実
  state/
    current.json        状態文書（schema 2、リビジョン管理）
    journal.jsonl       受理された書き込みの追記ログ
    .lock               短命の書き込みロック
  memory/
    atoms.jsonl         永続原子、1 行 1 JSON レコード
    .lock               短命の書き込みロック
  index.json            派生キャッシュ —— 削除して安全、必要時に再構築
  arch.json             任意のアーキテクチャ規則
```

`atoms.jsonl` は追記式で内容アドレス指定です。原子の id は「種別 + 正規化テキスト」のハッシュなので、同じ文を二度見ることはコピーを追記することではなく、**同じレコードを強化する**ことになります。`memory_forget` は行を削除せず墓碑を書きます —— 記録は証拠として残り、墓碑は粘着的なので後の抽出パスがそれを復活させることはできません。

`index.json` はキャッシュです。誤っているか削除されていれば、`memory_status` が再構築します。`current.json` が壊れている場合は `current.json.corrupt-<タイムスタンプ>` に改名され、黙って置き換えられるのではなく結果として報告されます —— 壊れたファイルは証拠です。

> このリポジトリ自身の `.dsh-memory/` は gitignore されています。それはプラグインの**出力**であり、プラグインそのものではありません。チームで記憶を共有したい場合は、自分のプロジェクトで無視を解除してください。

## 検証

```powershell
npm run setup        # インストール済み app.asar からホストパッケージを抽出してリンク
npm test             # 純粋な core/ 層に対する 14 個の単体テスト（DSH 不要）
npm run test:host    # 実際の harness に対する 12 個のホストレベル検査
```

`npm run setup` は `test:host` のための一度きり（かつ冪等）の前提です。`npm install` ではなく、インストール済みのデスクトップ版ペイロードからパッケージを読み出すので、テストはこのプラグインが将来ロードされるのと同じホストに対して実行されます。

`npm run test:host` は順に実行します:

| 検査 | 何を証明するか |
| --- | --- |
| `smoke.mjs` | モジュールグラフがロードでき、cordis プラグインの形をエクスポートする。 |
| `tools.mjs` | すべてのツールスキーマが harness の強制する JSON Schema サブセットに受理される。 |
| `cordis-semantics.mjs` | プラグインが依存するサービス解決の挙動を、仮定ではなく**測定**する。 |
| `inject.mjs` | ベースラインの合成、メッセージのタグ付け、サーフェスに基づく重複排除。 |
| `safety.mjs` | 保護パスの拒否、原本のバイト不変、トラバーサルの遮断、古い書き込みの競合、段落のデータとしての枠付け。 |
| `degrade.mjs` | 任意サービスが欠けていても 15 個のツールがすべて登録され機能する。 |
| `continuity.mjs` | 状態・決定・ブロッカー・文書が模擬再起動を生き延び、古さが実際に動く HEAD を追跡する。 |
| `root.mjs` | ルート発見: サブディレクトリは記憶を共有し、無関係なディレクトリは継承せず、git と設定が上書きする。 |
| `compat.mjs` | ホスト自身の `evaluatePluginCompatibility` がこのマニフェストを受理し、満たせない範囲を拒否する。 |
| `patch.mjs` | `cordis.patch.yml` がホスト自身の `bundlePatchPaths` 経由で解決し、ロード可能なプラグインを挿入する。 |
| `mount.mjs` | プラグインが実際の `ToolRuntime` とともに実際の cordis コンテキストへマウントし、きれいに破棄する。 |
| `loop.mjs` | 閉ループ: 圧縮イベントが実際のイベントバスを通じて原子を書き、次のステップがそれらを疎に呼び戻し、再生は冪等で、繰り返しは再注入されず、forget が尊重される。 |

`npm test` はパスの包含性、front-matter 解析、索引の導出、検索の順位付け、guard の枠付け、予算への適合、アーキテクチャ検査、原子的書き込み、ロック、状態のマージ、そしてい原子層全体（同一性、墓碑、疎なゲート、経路段階、抽出、ルーター、呼び戻し、圧縮オブザーバ）を網羅します。

ホストテストはいずれも抽出済みパッケージを必要とし、存在しない場合は**スキップ**します（終了コード 0）。スキップは `SKIP` と表示され、決して合格として数えられません —— 実行に `SKIP` が出たら、それは何も証明していません。

**スイートが緑であることは、インストールが機能していることと同じではありません。** スイートはリポジトリが構築した cordis コンテキストにプラグインをマウントするだけです。プロファイルが実際にロードすることを証明するのは、ホストを起動したときだけです。両方を行ってください: `npm run test:all`、そして再起動して `project_inspect` を呼ぶ。

## 設定

すべてのフィールドに有効な既定値があります。不正な値は修復され、致命的にはなりません —— 記憶プラグインが設定ファイルの誤字でセッションを止めるべきではありません。

| フィールド | 既定 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | マスタースイッチ。`false` なら何も登録しない。 |
| `injectContext` | `true` | 新しいセッションにベースラインを注入する。 |
| `announceToAgent` | `true` | システムプロンプトにガイダンスの節を追加する。 |
| `registerCommands` | `true` | 9 個のスラッシュコマンドを登録する。 |
| `l0Budget` / `l1Budget` | `300` / `1200` | 最小および完全ベースラインのトークン予算。 |
| `l2Budget` | `2000` | 1 回の読み取りのトークン予算。 |
| `maxDocuments` | `5000` | 索引化する文書数の上限。 |
| `gitTimeoutMs` | `4000` | git プローブのタイムアウト。遅い git がステップを妨げることはない。 |
| `includePrefixes` | `docs/`、`README.md` など | 索引化する対象。 |
| `excludePrefixes` | `.git/`、`node_modules/` など | 決して索引化しない対象。 |
| `protectedPaths` | `AGENTS.md`、`docs/decisions/` など | `docs_sync` が拒否するパス。 |
| `projectRoot` | セッションの cwd | 検出されたルートを上書きする。 |
| `extractOnCompaction` | `true` | 圧縮サマリを原子に変換する。 |
| `extractUserRules` | `true` | ユーザーが明示した規則を収穫する。 |
| `injectRecall` | `true` | ステップが recall ブロックを受け取れるようにする。 |
| `recallBudget` / `recallLimit` | `400` / `8` | 1 回の呼び戻しのトークン上限と原子数。 |
| `routerTier` | `smart` | `off`、`smart`、`always`。上の段階表を参照。 |
| `routerProvider` / `routerModel` | `''` / `''` | ルーターのモデル。両方設定されるまで `smart` は無料のまま。 |
| `routerReasoningEffort` | `''` | ルーターモデルへ透過（モデルが対応する場合）。 |
| `routerTimeoutMs` | `20000` | 1 回のルーター呼び出しの上限。 |
| `routerCooldownSteps` | `1` | 同じリクエストを再びルーティングするまで待つステップ数。 |
| `routerDigestBudget` | `900` | ルーターへ渡す原子ダイジェストのトークン上限。 |

## プロジェクト構成

```

  extract.js   サマリとユーザー規則からの決定的抽出
  state.js     状態文書、比較交換、ジャーナル
  indexer.js   文書索引      search.js    語彙順位付け
  context.js   トークン予算   guard.js     「指示ではなくデータ」の枠付け
lib/           cordis 層
  index.js     プラグイン本体、agent/pre-step 注入
  tools.js     15 個のエージェントツール   commands.js   9 個のスラッシュコマンド
  compaction-memory.js  session/event オブザーバ
  recall.js    1 ステップの呼び戻し   router.js    ルータープロンプトと解析

tests/unit/    純粋な core のテスト（node --test）
tests/*.mjs    実際の harness に対するホストレベル検査
docs/          設計ノートと文書提案
scripts/       テスト用のホストパッケージ抽出とリンク
```

`docs/design/system-c-memory-atoms.md` は原子層とゲートを詳しく説明しています。**読むことではなくテストすること**で見つかった二つの実装上の罠も含みます（生のスコアに対する softmax は単一エキスパートに崩壊する。重なりだけで順位付けると、ハードな制約が最も必要なときに捨てられる）。

## 既知の制限

[LIMITATIONS.md](./LIMITATIONS.md) を参照してください。要約: 検索は意味的ではなく語彙的です。ルーターは `routerTimeoutMs` で上限が定められ、失敗時は決定的選択へ降格します。原子は権威ある文書ではありません。自動コミット、プロジェクト間クエリ、クライアント UI はありません。

ルーターサブエージェントは**実際のモデルに対して一度も実行されていません**。単体テストはスタブ化したデリゲートでタイムアウト、中断、不正な応答、未知の id を網羅し、その構築は実際の `startActivation` シグネチャに対して検査されています —— しかし実際の spawn が実際の選択を生み出したことは観測されていません。失敗時は決定的選択へ降格するので、最悪の場合は改善の機会を逃すことであり、ステップが壊れることではありません。
